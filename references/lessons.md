# 实践中踩过的坑

示例片做了六个版本，下面是每一步暴露的问题和最后的改法。遇到新情况，先看这里有没有类似的。

## 风格和质感

| 问题 | 为什么不行 | 改法 |
|---|---|---|
| 背景用 AI 生成的电影感图（熔炉、赌场、神殿） | 一眼就假，显得廉价 | 舞台只用中性纹理；人物和事件用真实素材 |
| 元素各自演入场：弹出来排队、重排成田字格、贴皇冠、打字机、扫光 | PPT 感 | 东西自己只淡入（约 0.25 秒）或切过来就在；大运动交给镜头和原地换状态（`motion.md`） |
| 清楚的实拍上压标题、贴名牌框 | 同样廉价 | 只留两种压法：人抠出来站在巨字前面；实拍压暗去色退成底、字是主角 |
| 用低清百科视频 | 画质一看就不行 | 换官方 1080p 宣传片和纪录片 |
| 整张平面一起慢慢缩放（没有目标、多半往外拉） | 廉价，像幻灯片在呼吸 | 镜头在有前后层的舞台里走：快速换位到正在讲的东西，再慢漂往里推 |
| 把慢推全删掉 | 三分之二的时间整屏定住，片子死了 | 同上；交片前用 `motion_check.py` 量 |
| 每个数都滚 | 装饰，不是内容 | 只在“累加”本身是意思时滚，一条片一两次，满位数、按十亿取整 |
| 英文副标题、章节牌、来源小字到处都是 | 太多小字，看着累 | 一镜最多一个短的中文标签；一帧最多一组眉题 |

## 素材和逻辑

| 问题 | 为什么不行 | 改法 |
|---|---|---|
| 念到公司名就切航拍 | 看不出是谁家的楼 | 身份要在画面里：脸、logo、写着名字的新闻标题 |
| 镜头之间硬切，素材只停零点几秒 | 前言不搭后语，前因后果看不出来 | 先写导演表，逐镜写“承接”一列；实拍至少停 1.5 秒左右 |
| 资金关系图中间插一段全屏新闻片 | 打断关系图 | 新闻做成小卡，从箭头旁弹出，读完缩回去 |
| 直接插 CEO 原声 | 观众不知道他是谁、为什么在这说 | 先加铺垫句，画面上也做交接 |
| 结尾放一段好看但和内容无关的航拍 | 跟论证没关系 | 结尾回到全片那个数字和开头那几家公司 |
| 收到修改意见后换了一种风格重做 | 偏离了已经认可的版本 | 在原版上逐镜改；改动多时先列清单确认 |

## 动效、剪辑和包装

和参考片放在一起看，第五版差得很远。逐帧量了参考片的镜头运动以后，问题和改法如下（原理见 `motion.md`）：

| 问题 | 为什么不行 | 改法 |
|---|---|---|
| 人和图形从不一起动 | 参考片最招牌的动作全没有 | 用当事人的实拍抠像演：人站在巨字前面、人身后换背景、横推换人、卡片在人旁边冒出来 |
| 东西摆好以后整屏定住 2–9 秒 | 死 | 每镜有机位：快速换位 → 慢漂 → 下一刀 |
| 新东西一张张砸到最上面 | 元素在演 | 东西早就摆在世界里，镜头去找它（新闻卡铺成桌面、镜头滑过去；关系网里镜头摇去找正在说的那家） |
| 只有淡入和硬切，没有前后层 | 平 | 分层相机（远的动得少）、方向运动模糊、景深；上一镜虚化当底、平面倒成桌面 |
| 横推换人的前几帧露出了采访者 | 原片的切点比入点晚 | 抠像前逐帧查切点，`matte.py --from` 跳过 |
| 巨字被人挡住一半 | 人在原片里走动 | 按每帧头肩中心把人钉在两组字的空当里（`matte_clean.py` + `stage25d.js` 的 track） |
| 画框底部露出原片烧进去的字 | 抽帧没裁 | 抽帧时放大裁掉 |
| 一次批评变成了全局禁令 | “慢推廉价”被理解成“不许动”，结果片子死了 | 先分清是手法不对还是做法不对，拿参考片同一个手法的连续帧对照 |

## 开头

| 问题 | 改法 |
|---|---|
| 没信息量的空镜开场 | 用关键词钉在中央的快闪，垫在第一句话下面 |
| 新闻卡随机乱叠 | 关键词固定在屏幕正中，周围的出处在换 |
| 旁白前空等两秒放快闪 | 缩到 0.3 秒就开口 |
| 搜索引擎拦截截图 | 用核实过的文字自己排效果图，不仿真实网站 |

## 声音

| 问题 | 原因 | 改法 |
|---|---|---|
| 语速时快时慢 | 每句前后带着 0.2–0.6 秒静音，再加上停顿 | 每句切掉首尾静音，停顿只由 gap 决定 |
| 语速听着急促 | 切掉静音后又拉了 1.1 倍 | 保持原速 |
| 配乐“怪” | 紧张滴答乐和放映机声 | 去掉，只留平稳的底乐和轻翻书声 |
| 原声里有“异响” | 句尾砍掉半个词；截进了一段数字静音 | 剪口按波形定 |
| 字幕和卡点全错 | 对齐脚本用文件名前三个字当键，b10b 覆盖了 b10 | 键用完整编号 |

## 工程

| 问题 | 改法 |
|---|---|
| 交出去的文件打不开（合成没写完） | 每个文件用 ffprobe 验证过再交 |
| 合成时 ffmpeg 卡死 | 在一个大滤镜图里同时读带画面的 mp4、图片和多条音轨会互相等待；音频先抽成 wav，字幕和音频分开合成 |
| yt-dlp 403 | `pip install -U yt-dlp` |
| edge-tts 403 | `pip install -U edge-tts` |
| 实拍黑屏或空框 | 新素材的帧数没登记 |
| 停住的画面露出下一个镜头 | 抽帧时出点压在了镜头切点上 |
| 荧光笔和文字对不齐 | 字体加载完以后再量、再截 |

## 手法库

- 这份 skill 一开始只有原则和工具，镜头全靠现写：能力强的模型驾驭得住，弱一点的模型每条片都会重新摔一遍同样的跤，质量不稳。
  → 从第六版拆出底座 `film_base.js` 和手法库 `moves.js`，起步用 `starter/`。手法只管动作，画面由片子传；每个手法写清“说的是 / 不适配的时候”；调用要写 why；`render.mjs --moves` 查用量和与上一条片的重合。
  → 复用是为了稳定质量，不是为了模板化：先想这一镜要说什么，再找最对得上的手法；只是差不多就手写，不要为了出片去凑手法。

## 模板档

- 有了手法库，每一镜的画面还是要现写，对模型的要求还是高。
  → 加模板档 `kit/`：一条片 = 一张镜头表，每镜选一个场景、填内容、写 `says`；镜头、出现方式、前后层、字号颜色都由模板管。时刻写成 `'@句:词'`；`render.mjs --check` 用文字报错和提醒（有的模型看不了图），`--sheet` 每镜三帧拼一张图。硬规则在 `references/rules.md`。目标是让弱一些的模型也能稳定出片，这一点还没实测过。
  → 原来的手写档（`film_base` + `moves` + `stage25d`）留着：模板对不上的那一镜写 `scene:'custom'`，或者整条手写。
  → 选场景仍然按“这句话在说什么”，不按顺序套。模板是词汇，不是镜头顺序。
- 模板档第一版的示例片全是图形：没有真人、真新闻；斜着的 3D 卡片墙、手机、标题墙；整屏紫、青、酒红底和大团颜色光；织物底是一块块的噪声；前景有浮尘。
  → 按原版的做法，用真素材手写了一条 28 秒的《谷歌给苹果的两百亿》（`examples/google-apple-20b/`）。kit 的默认画风照这条和原版返工：细斜纹深蓝织物底；`tone` 只留 navy、charcoal、wine；颜色光只给 `person`；去掉浮尘；3D 改平，只留“新闻摊在桌面上”和“倒成桌面”两种透视；照片圆盘；原文摊在织物上，不整屏白。
  → 交片前和 `examples/ai-burn-money/frames_1fps.jpg` 并排抽帧比，是硬步骤，不是可选。
- 交付时只笼统写了“用了 skill”，其实谷歌那条只用了截新闻和渲染两样。
  → 交付说明里写清实际用了哪一档、哪些脚本。
