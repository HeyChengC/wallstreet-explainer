# 案例：《谷歌给苹果的两百亿》（2026-10-31，28 秒）

模板档第一版的示例片全是图形、满屏 3D、底色难看。之后按原版的做法，用真素材手写了这条短片。kit 的默认画风就是照这条和原版（`../ai-burn-money/`）返工的。

**不要照着它的镜头顺序做新片。** 学的是：实拍和新闻是主角、底只有一张细斜纹织物、图形只用来演钱和关系、每一镜都接住上一镜。

- `script.txt`：文案（豆包 2.0 配音，一次合成，27 秒；字级时间用 faster-whisper 对齐）。
- `film_index.html`：整条片的页面，手写档最小的样子（不用 film_base，只有 `window.ready` 和 `window.seek(t)`，`render.mjs` 直接渲）。素材和成片抽帧都有版权，不随仓库给，页面只用来读。
- `fabric.py`：细斜纹深蓝织物底的生成脚本（kit 的 `make.py` 照它改的）。
- `matte_full.py`：CPU 上整帧抠人（和 `matte.py` 同一个 ISNet 模型；没有显卡时用）。

## 为什么这么做（对着第一版示例片的毛病）

- **不再全是图形**：28 秒里有 6 镜是真东西：官方广告实拍 2 段、4 篇新闻原文、当事人实拍抠像。图形只有圆盘连线、金色数字、两根柱子三样，都在演钱。
- **不要满屏 3D**：透视只有一种：新闻摊在桌面上。其余都是平的，靠镜头推拉和前后层出空间。
- **底色**：全片一张很细的斜纹深蓝织物，中间略亮；只在皮查伊身后换成谷歌蓝的同一种织物。没有紫底、没有大团彩色光、没有浮尘。
- 数字一律金色渐变 Bebas Neue，中文单位用数黑体；原文刷黄用正片叠底，从左往右刷。

## 和原版比还差的（交片前并排比过）

- 原版有当事人原声收尾（扎克伯格），实拍比例更高；这条 28 秒没留原声。片子长一点就要留一段原声。
- 原版柱子那段是酒红底、柱子站在台上；这条用深蓝织物 + 倒影，干净但没那么"算总账"。

## 做的时候踩的坑

- **交出去的第一版 1080p 结尾 3.5 秒是空的**（金句和字幕都没了）：出 1080p 前改了一处 HTML，把第 7 镜的 `</div>` 改坏，第 8 镜和字幕被套进第 7 镜一起藏了。改完只看了两张静帧。现在的 `film_index.html` 是修好的；`render.mjs --video` 渲完会自动报空画面。教训：改了页面就整片重渲 720p 从头看到尾，再出 1080p。

- YouTube 只截一段：`--download-sections` 和 HLS 格式都会断，用 `-f 137`（https dash）拿直链再 `ffmpeg -ss -t -c copy`。见 `references/sourcing.md`。
- 镜像下抠像模型会断，续传可能拼坏文件：对 `X-Linked-Size` 和 sha256。
- `render.mjs` 的本地服务器根目录是片子目录，`../` 引用的字体会 404：字体拷进片子目录。
- 苹果广告里 Safari 图标那镜只有 0.6 秒：开头只能放慢用。
- 页面要按 `innerWidth/1920` 缩放整个舞台，不然 720p 渲出来只有左上角。
